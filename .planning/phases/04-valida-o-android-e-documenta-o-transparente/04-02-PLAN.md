# Plan 04-02 — Verificação de runtime no emulador Android (camada VERIFIED)

## Objective

Usar o emulador Android disponível (`Medium_Phone_API_36.0`) para VERIFICAR o
comportamento de runtime que os testes unitários da Phase 3 não comprovam:
MethodChannel Kotlin realmente registrado, `ConnectivityManager` /
`activeNetwork` / `NetworkCapabilities` / `LinkProperties` / gateway de rota
default, permissões do manifest final instalado, e o fluxo real da tela de
Diagnóstico. Promover a **VERIFIED (Android Emulator)** apenas cenários
realmente reproduzidos no emulador; nunca marcar **dados móveis** como VERIFIED
em emulador (D-06). Se um bug real de runtime for encontrado, corrigir no lugar
certo, adicionar teste regressivo quando possível, e rerodar gates.

## Artifacts this phase produces

- Atualiza `04-ANDROID-VALIDATION.md` com linhas VERIFIED (Android Emulator) e observações.
- (Condicional) correção de código + teste regressivo somente se um defeito de runtime for encontrado.

## Tasks

### Task 1 — Confirmar toolchain, device e build de runtime

<action>
Confirmar Flutter em `C:\src\flutter\bin\flutter.bat` e o AVD
`Medium_Phone_API_36.0`. Bootar o emulador, aguardar boot completo (adb
`sys.boot_completed`), e fazer um build/instalação de debug do app de produção
(`flutter run` ou `flutter build apk --debug` + `adb install`). Registrar se o
app inicia sem crash e se os MethodChannels
`br.dev.rodrigopinheiro.tools_app/network_snapshot` e `/share_text` respondem
(verificado pela tela de Diagnóstico produzir fatos de snapshot, não erro de
canal). Isto prova o item "MethodChannel realmente registrado" (não apenas
compila).
</action>
<read_first>
- android/app/src/main/kotlin/com/example/tools_app/MainActivity.kt
- android/app/src/main/kotlin/com/example/tools_app/NetworkSnapshotPlugin.kt
- lib/diagnostic/diagnostic_defaults.dart
</read_first>
<acceptance_criteria>
- Emulador em estado `device` no `adb devices`.
- App de produção instala e abre sem crash no emulador.
- A tela de Diagnóstico obtém um snapshot real (transporte/capabilities) via canal — sem MissingPluginException.
</acceptance_criteria>

### Task 2 — Reproduzir e VERIFICAR cenários de plataforma no emulador

<action>
Na tela de Diagnóstico rodando no emulador (Wi-Fi virtual do host), executar um
diagnóstico e observar: transporte (wifi), INTERNET/VALIDATED, IPv4 local real
do link, gateway da rota default (ou indisponível honesto), IP público via ipify
(HTTPS), TCP connect ao gateway, HTTPS probe ao gstatic 204, min/média/máx +
denominador, cancelamento, e comportamento offline (adb `svc wifi disable` /
airplane) sem spinner infinito. Usar `adb logcat` para observar. Promover a
**VERIFIED (Android Emulator)** somente os cenários realmente reproduzidos e
observados. Marcar como NOT VERIFIED o que o emulador não reproduz de forma
confiável (ex.: captive portal real, troca Wi-Fi↔celular real). **NUNCA** marcar
dados móveis como VERIFIED no emulador (D-06).
</action>
<read_first>
- lib/diagnostic/session/diagnostic_session_impl.dart
- lib/diagnostic/platform/android_network_snapshot_source.dart
- .planning/phases/04-valida-o-android-e-documenta-o-transparente/04-ANDROID-VALIDATION.md
</read_first>
<acceptance_criteria>
- Cenários reproduzidos (Wi-Fi, IPv4 local, gateway, IP público, TCP, HTTPS, offline, cancelamento, min/média/máx) recebem nível VERIFIED (Android Emulator) com observação específica do ambiente.
- Dados móveis permanece NOT VERIFIED (requer Android físico com rede celular real).
- Cada linha VERIFIED cita evidência concreta (observação de tela / logcat).
</acceptance_criteria>

### Task 3 — Se um defeito de runtime for encontrado, corrigir e regressar

<action>
Se qualquer cenário revelar um bug real (ex.: canal não registrado, parsing de
snapshot incorreto, gateway inventado, spinner infinito), registrar o cenário na
matriz, corrigir no arquivo correto (Kotlin/Dart), adicionar teste regressivo
quando viável, e rerodar `flutter analyze --no-pub` + `flutter test --no-pub`.
Não mascarar defeito nosso como "limitação conhecida". Se nenhum defeito for
encontrado, registrar explicitamente "nenhum defeito de runtime encontrado".
</action>
<read_first>
- lib/diagnostic/platform/android_network_snapshot_source.dart
- android/app/src/main/kotlin/com/example/tools_app/NetworkSnapshotPlugin.kt
</read_first>
<acceptance_criteria>
- Qualquer bug encontrado é corrigido no lugar certo e a matriz registra o cenário + correção.
- analyze limpo e testes verdes após qualquer correção.
- Se sem defeitos: a matriz afirma "nenhum defeito de runtime encontrado no emulador".
</acceptance_criteria>
