# Plan 05-01 — Pesquisa/evidência atualizada por candidato (bloco 1)

## Objective

Conduzir **pesquisa documental atualizada** (não copiar a existente — D-10) sobre a
viabilidade de um futuro teste de velocidade, coletando **evidência citável** para
cada critério obrigatório do gate, por candidato. Produz `05-EVIDENCE.md`: um dossiê
de fontes por candidato, com status preliminar por critério (`PASS`/`FAIL`/
`INSUFFICIENT`/`N/A`) **sempre acompanhado de fonte** — sem linguagem especulativa
como base de PASS (D-04). Este bloco NÃO decide o gate e NÃO implementa nada.

**Escopo negativo (proibições — CONTEXT D-14, D-20):** não implementar speed test;
não adicionar SDK/plugin ao produto; não alterar `lib/` ou `android/`; não usar
WebView/endpoint informal/engenharia reversa; não liberar SPD-*.

## Artifacts this phase produces

- Novo arquivo: `.planning/phases/05-gate-de-viabilidade-do-speed-test/05-EVIDENCE.md`
  (dossiê de evidência por candidato; nenhuma alteração de código)

### Task 2 — Coletar evidência documental por candidato

<action>
Para cada candidato, coletar **somente fontes documentais públicas** (documentação
oficial, ToS/AUP, política de privacidade, preços, licença/repo) e registrar, por
critério: o status preliminar (`PASS`/`FAIL`/`INSUFFICIENT`/`N/A com justificativa`)
e a **fonte** (URL + o que ela comprova + data de acesso). Sem fonte suficiente →
`INSUFFICIENT` (D-09). Não usar WebView/endpoint informal/engenharia reversa (D-14).
Não contatar fornecedor comercial (D-16); se um critério obrigatório só puder ser
resolvido por contato e não houver info pública, marcar `INSUFFICIENT` + condição de
reavaliação. Registrar explicitamente casos onde uma licença de SDK NÃO comprova
autorização de infraestrutura (D-13).
